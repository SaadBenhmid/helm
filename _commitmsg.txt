fix(P1a/P1b/P2): nested-app verify cwd, verify execution-boundary notice, lint artifact gap

Addresses the remaining three findings from the external audit (ChatGPT).

P1a — verify runs in the detected package's directory:
  detectStack surfaces `target` for a nested monorepo app (apps/web, packages/*),
  but `helm verify` ran install/build/test from the repo root, verifying the wrong
  (or no) app. New pure `verifyCwd(stack, root)` resolves the run dir; the command
  now spawns each step with `cwd` set to that package. Logs the nested target.

P1b — verify is labelled an execution boundary, not a safety boundary:
  verify runs the project's OWN install/build/test scripts in a real shell; the
  allowlist only limits which package-manager verbs run, not what they do. Added a
  one-line CLI notice before execution and a README warning. Only verify trusted code.

P2 — lint flags missing phase artifacts:
  artifacts are Helm's durable memory, but lint only checked memory logs/order and
  reported "healthy" even when a completed phase never wrote its artifact. lintMemory
  now takes phaseArtifact + artifacts and warns when a completed (or in-progress
  current) artifact-bearing phase lacks a real (non-stub) artifact. A not_started
  phase is exempt (no false nagging). On this repo, lint now correctly warns that
  the completed `validate` phase has no VALIDATION.md.

Tests: +3 verifyCwd cases, +3 lint artifact cases. 262/262 passing.
